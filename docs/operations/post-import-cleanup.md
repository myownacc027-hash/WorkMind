# Завершение исторического импорта: проверка, очистка и резервные копии

> **Статус:** обязательный операционный чек-лист, не автоматическое удаление. Отслеживание: [GitHub issue #7](https://github.com/myownacc027-hash/WorkMind/issues/7). Изменения кода конвейера: [PR #6](https://github.com/myownacc027-hash/WorkMind/pull/6).

## Когда выполнять

**Только после** завершения всех этапов: (1) импорт пятилетней истории из всех включённых Outlook-папок, (2) обработка и индексация накопленных вложений, (3) принятие решения по ошибкам и документам с усечённым текстом, (4) проверки целостности, поиска и резервного восстановления.

Завершение mail-first импорта **не означает** завершения обработки вложений. `completed` у задания вложения не означает успешного индексирования текста: `unsupported`, `empty_no_text` и другие терминальные статусы требуют отдельной сверки. Большие Excel могут быть `indexed`, но содержать `metadata_json.truncated=true`.

Задачу #7 не закрывать до фактической очистки и контрольной проверки. Ни запуск скрипта, ни слияние PR #6, ни истечение срока хранения не означают разрешения на удаление.

## Контрольные условия (все обязательны)

- [ ] Нет активных импортёров, attachment/email workers, backup/restore и расписаний, которые читают или пишут в удаляемые каталоги.
- [ ] `history_import_states`: все включённые папки обеих областей (primary/archive) прошли заданное окно времени; `running`, `paused` и ошибки разобраны. Наличие незатронутых папок объяснено, а не принято за завершение.
- [ ] `processing_jobs`: нет `pending`, `processing` и неразобранных `error` для `index_email` / `index_attachment`. Утверждён перечень исключений, если такие есть.
- [ ] `attachments`: сверены статусы `indexed`, `unsupported`, `empty_no_text`, `corrupt`, `error`; `truncated` и парсер XLS/XLSX проверены отдельно. Все важные исходные документы остаются в CAS.
- [ ] PostgreSQL и Qdrant прошли `workmind-index-admin check` после завершения записи; проверены реальные поисковые запросы, исходные ссылки, письма и вложения.
- [ ] Проверено отсутствие недостающих CAS-объектов, проблемы с переносом/ссылками, несогласованность хешей при восстановлении.
- [ ] **Создан новый полный бэкап после завершения обработки** и получен `BACKUP VERIFY: PASS`; по возможности выполнено изолированное тестовое восстановление. Предшествующая проверенная копия сохраняется до подтверждения результата нового восстановления.
- [ ] Составлен отдельный отчёт кандидатов на очистку без удаления: путь/категория, размер, возраст, назначение, причина, связь с активным процессом, предлагаемое действие.
- [ ] Владелец WorkMind согласовал конкретные объекты и резервные точки, которые разрешено удалить, и места хранения оставшихся копий.
- [ ] По завершении удаления повторно проверены конфигурация, состояние очередей и поиск.

## Какие данные сохраняются всегда, пока они используются

**Не удалять при уборке:** `WORKMIND_HOME/archive/objects` (CAS), исходные письма/документы, PostgreSQL database/volume, Qdrant collection/storage/volume, используемые embedding models, `.env` и другие локальные настройки/секреты, Alembic migrations, рабочие статусные файлы/локи и актуальные логи, каталоги текущей задачи. Нельзя считать `unsupported` вложения «мусором»: часто это изображения/архивы, но их оригиналы должны оставаться в CAS до отдельного решения о политике хранения.

Не использовать в качестве «очистки»: `docker compose down -v`, `docker volume prune`, `docker system prune --volumes`, массовые удаления по маске в корне `WORKMIND_HOME` или в папке бэкапов.

Для Windows проверить, что путь не junction/reparse point или symlink, ведущий в действующий каталог данных. Различные буквы дисков **не гарантируют** физической независимости хранилищ.

## Возможные кандидаты — только после отчёта

| Категория | Как оценивать | Особые ограничения |
| --- | --- | --- |
| Исторические `history-auto-*`, `history-mail-first-*` журналы | Дата, объём, диагностическая ценность | Оставить журнал последнего успешного запуска и журналы проблемных проходов до приёмки |
| Одноразовые диагностические выгрузки/temporary snapshots | Существуют ли ссылки из актуальных отчётов и процессов | Только явно идентифицированные и неиспользуемые |
| Устаревшие локальные runner scripts и stop/status-файлы | Проверить Scheduled Tasks, Startup, PID/процессы | Не удалять текущие `history-import-status.json`, логи и активные флаги |
| Тестовые Git worktrees | `git worktree list` + `git status` каждого worktree | Удалять через `git worktree remove`, не удалять рабочие изменения |
| Старые `WorkMindBackup-*` | `manifest.json`, размер, версия, дата, статус VERIFY, успешное восстановление | Не удалить последний пригодный бэкап; не удалять точку до миграции, пока не проверена новая |
| Временные Qdrant snapshots / Docker build cache | Сверить с активными контейнерами, backups и volumes | Никогда не удалять данные persistent volumes общей командой |

## Резервные копии: переходная и постоянная политика

**Во время миграции:** сохранять исходную проверенную точку перед обновлением и независимо проверенную новую точку после окончания всех этапов. Убирать старые копии только после проверки восстановления из новой точки и согласования с владельцем.

**После стабилизации:** установить явное правило BACKUP-02 (плановое 7 daily / 4 weekly / 6 monthly записано в [backup-and-restore](../backup-and-restore.md), но пока **не реализовано**). Проверить фактическую стоимость полной копии и необходимость хранения Qdrant snapshot: его можно пересоздать из PostgreSQL/CAS ценой долгой повторной индексации.

Минимально сохранять одну независимую проверенную точку восстановления после завершённого импорта. Для защиты от отказа диска иметь копию вне того же физического диска/узла; копия на том же D:, что и живые данные, не является защитой от отказа D:.

Не вводить автоматическое удаление резервных копий до отдельной реализации, тестов retention, dry-run, исключений/защиты последней копии, журнала операций и явного включения.

## Безопасная инвентаризация в PowerShell 5.1 (без удаления)

Запускать из корня проекта при наличии `.venv`. Команда выводит кандидатов, **ничего не стирает**:

```powershell
$homeDir = (& .\.venv\Scripts\python.exe -c "from packages.common.config import get_settings; print(get_settings().workmind_home)") | Select-Object -Last 1
$logsDir = Join-Path $homeDir "logs"
$runDir = Join-Path $homeDir "run"

Get-ChildItem -LiteralPath $logsDir -Directory -ErrorAction SilentlyContinue |
    Where-Object { $_.Name -match '^history-(auto|mail-first)-' } |
    Sort-Object LastWriteTime |
    Select-Object FullName, LastWriteTime

Get-ChildItem -LiteralPath $runDir -File -ErrorAction SilentlyContinue |
    Select-Object Name, Length, LastWriteTime

git worktree list

# Explicitly choose the backup root, then list candidates (read-only):
$backupRoot = "<backup-root>"
Get-ChildItem -LiteralPath $backupRoot -Directory -Filter "WorkMindBackup-*" |
    Sort-Object LastWriteTime |
    Select-Object FullName, LastWriteTime

# This does not stop containers, remove volumes or delete backup directories.
```

Для оценки размера каталогов использовать отдельную read-only инвентаризацию. Не использовать произвольные `Remove-Item -Recurse` до сверки путей/junction и подтверждения списка.
